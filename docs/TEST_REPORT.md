## Bugs by severity

### High (would hurt scoring or credibility)

**B1. README Option B step 1/2: wrong zkool binary path.** README.md lines 56 to 65. The README clones zkool2 *inside* the hisaab repo (`git clone … && cd zkool2/rust`), then `cd ../..` returns to the hisaab root, but `ZKOOL_BIN=../zkool2/target/release/zkool_graphql` points one level too high (zkool2's workspace target is `zkool2/target/`, confirmed on this machine at `…/freesociety-nikhil/zkool2/target/release/zkool_graphql`). `scripts/zkool-up.sh` then runs a non-existent binary and prints "failed to start" after 60 s.
Fix: README.md line 65 to `ZKOOL_BIN=zkool2/target/release/zkool_graphql scripts/zkool-up.sh all` (and add `zkool2/` to `.gitignore`), or clone zkool2 next to the repo (`cd .. && git clone … && cd zkool2/rust`).

**B2. README step 3 to 4: the key the next command needs is never shown.** README.md lines 67 to 72. Step 3 says it "prints addresses and the freelancer's public keys only", but `scripts/demo-wallets.mjs` line 48 prints the UIVK truncated to 24 chars plus an ellipsis; the full key is only in `data/demo-wallets.json`. A judge pasting `uivktest1...` fails with "Malformed viewing key".
Fix: README.md line 72: `node bin/hisaab.js connect --key "$(node -p "require('./data/demo-wallets.json').freelancer.uivk")" --birth "$(node -p "require('./data/demo-wallets.json').freelancer.birth")"`. Also change the "prints ... public keys" wording on line 67.

**B4. README contradicts itself on whether the CA needs a key.** README.md line 33: "…and the CA's check needs no key." But line 99 (and the pack's `README-for-CA.md`) say `verify` needs a Hisaab watch-only account, i.e. the client's viewing key; section 5 item 4(b) lists "verifiable receipts without ever being handed the key" as *future* work. This is the exact privacy claim a Privacy-track judge will probe. SUBMISSION.md line 22 ("The CA runs hisaab verify on any receipt") has the same implication.
Fix: README.md line 33, replace with "…and the CA can check the pack's integrity with `sha256sum -c` without any key; checking amounts and memos against the chain needs the viewing key (receipts that need no key are on the next-steps list)." Same one-line caveat in docs/SUBMISSION.md Description.

**B5. Every testnet explorer link generated by the code points to the explorer that returns "Transaction not found".** `src/network.js` line 6 (`zexplorer.app/testnet/tx/{txid}`), also `src/ledger.js` line 10, `src/pack.js` line 128, `scripts/demo-pay.mjs` line 38. I fetched the real txid `d78fd57a…4541`: zexplorer.app returns "not found" (twice on the page); `testnet.zcashexplorer.app/transactions/<txid>` shows it (block 4582622, shielded). So ledger.csv, receipts, UI links and the CA pack all link to a dead page for every current tx, while the README tells judges to use the other site. The video's end card (`scripts/make-video.cjs` line 42, visible at 1:45) also shows the dead zexplorer link right after a card saying it is behind.
Fix: `src/network.js` line 6: `test: 'https://testnet.zcashexplorer.app/transactions/{txid}'`; make `ledger.js` line 10 use `explorerTx`; update `pack.js` line 128 text and `demo-pay.mjs` line 38. The video cannot be re-rendered cheaply; at minimum make README say the end-card link is dead and the working one is the README's.

### Medium

**B3. README Option A overclaims and omits the connect step.** README.md line 45: "It shows the UI and the invoice-to-paid loop". In the mock, a newly created invoice can never become paid (the mock's fixture memos are fixed codes `HSB-7K2M9Q` etc., and new invoices get random codes), and the commands as written stop before `connect`, so a judge sees an empty "connect a key" UI. Fix: add to Option A `node bin/hisaab.js connect --key <UIVK printed by the mock> --birth 3700000` (the mock prints the key on start), and reword to "shows the UI, ledger, pack and verify against fixture data; invoice matching is covered by the unit tests".

**B6. Placeholder text left in README.** README.md line 174: `MAINNET_TXID_PENDING`. Reads as unfinished, and "Also runs on mainnet" heads a section with no mainnet transaction. Not a false claim (it says pending), but with ~1h45m left either add the txid or delete the sentence and retitle the section "Mainnet mode (watch-only, not exercised with a real payment)".

**B7. Privacy note omits where the viewing key lives.** README.md line 117 and SUBMISSION.md say Hisaab stores "invoice codes, descriptions, txids, amounts and memos … and nothing else". `src/service.js` line 151 writes the viewing key itself into `data/config.json` (mode 600, plaintext), and the zkool watcher DB is started with `--allow-unencrypted-database` (`scripts/zkool-up.sh` line 21). The Private criterion scores honesty about what is stored. Fix: add "the viewing key (`data/config.json`, and zkool's unencrypted watcher database)" to that bullet; item 4(c) "encrypt data/ at rest" already covers the fix.

**B8. Video states things the README deliberately does not.** `scripts/make-video.cjs` line 29: "Mainstream crypto-tax tools can't see shielded transactions". README.md line 25 and `docs/research-needed.md` section 2 only support CoinTracker and Koinly (KoinX/CoinLedger/ZenLedger marked UNVERIFIED, "claim nothing"). Also line 38 of the same file says the server "Stores invoice codes and txids locally" (README also lists descriptions, amounts, memos). Video is already rendered, so the practical fix is a pinned comment/README note: "the video's 'mainstream tools' line is verified for CoinTracker and Koinly only", and align the trust card wording if re-rendered.

**B9. Pack README cites tax section numbers the research doc says are unverified for FY 2026-27.** `src/pack.js` line 147: "section 115BBH (30%), with TDS under 194S". Under the Income-tax Act 2025 (in force 1 Apr 2026, which covers FY 2026-27) the numbering is unconfirmed (`docs/research-needed.md` section 1). Fix: "taxed at a flat 30% with 1% TDS (section numbers: 115BBH/194S under the 1961 Act; the Income-tax Act 2025 renumbers, check with your CA)".

**B10. "Continuing" evidence not yet real.** README.md lines 165 to 168 and SUBMISSION.md say the zkool2 issue is "drafted … (to be filed)". The rubric's Continuing criterion (and tie-break) wants a concrete step taken, linked. If there is time, file `docs/upstream-zkool2-issue.md` on hhanh00/zkool2 and a forum post, then link them in README section 7. The pilot with a CA is honestly marked "not started".

### Low

- **B11. No upper bound on amount.** `src/invoices.js` lines 94/129 only check `> 0`. `invoice new --amount 21000000.00000001` and `--amount 1000000000` succeed. Fix: reject `amountZats > 21_000_000 * 100_000_000`. (0, negative, 9 decimals, `abc`, `1e3`, `1,5`, empty are all correctly refused.)
- **B12. Over-long description is silently truncated in the memo.** A 600-char description is accepted by the CLI (UI input has `maxlength=300`); memo is cut to 512 bytes (`HSB-CNWS72`: memo 512 B, description 600 chars), multi-byte text is cut on a character boundary (511 B), but the user is never told. Fix: warn in `newInvoice` or cap description at 200 chars.
- **B13. Mempool rows are printed in every FY's ledger** (`src/service.js` line 188: `pending` is not FY-filtered). `ledger --fy 2025-26` shows the mempool payment from 2026-27. They are excluded from totals, so numbers are right, but it looks odd to a CA.
- **B14. Unit label "ZEC" on testnet.** `web/index.html` line 107 column header and the CLI ledger columns say ZEC while the invoice form says TAZ. Cosmetic; set from `s.coin`.
- **B15. README technology list "with versions"** (AGENTS.md checklist): no versions for lightwalletd, Playwright, ffmpeg, CoinGecko API; ZIP 317 is listed but no Hisaab code uses it (fees come from zkool). Remove ZIP 317 or say "fees paid by zkool per ZIP 317".
- **B16. Build-time wording.** README.md line 43 says "about 30 minutes ... or a prebuilt binary if one exists", FEEDBACK.md says it took 43 min and that v6.36.0 *does* ship a prebuilt asset. Tell the judge directly: "use the zkool2 v6.36.0 release asset `zkool_graphql`". Option B cannot be done in 15 min from source.
- **B17. Dead no-op in UI.** `web/index.html` `$("#connectCard").open = !connected;` — `#connectCard` is a `<section>`, not `<details>`; harmless.
- **B18. Possible deadline mismatch to verify.** AGENTS.md "For the agent" says to finalize on Stadium "by 20:00"; docs/SUBMISSION.md says "before 00:00 IST, 5 Nov". Confirm against the Stadium page.
- **B19. Stadium viewing-key field.** The AGENTS.md checklist names `uviewtest…` (UFVK); README/SUBMISSION give a `uivktest1…` UIVK. Stadium's tooling may only accept the UFVK prefix. The demo freelancer wallet only receives, so adding its UFVK (in `data/demo-wallets.json`) as an alternative costs nothing; do not paste it from this report, read it from the file.

## 3. Security evidence (PASS)

- `git log -p --all` (9 commits, 309 KB) scanned with regexes for: `secret-extended-key-*1…`, `usk(test)1…`, `xprv/tprv`, `zxviews*`, private-key PEM blocks, GitHub/OpenAI/AWS/CoinGecko tokens, `api_key|secret|password|token = …`, bearer tokens, 12 to 24-word mnemonics. Hits: none, except the BIP-39 public test vector `abandon … about` used as a *negative* test input (test/*.test.js) and the string `zxviewtestsapling` in a test list. `data/`, `out/`, `.env`, `*.db`, `media/` are git-ignored and absent from history; `.env.example` has placeholders only.
- Viewing keys in history: one real UIVK (README + SUBMISSION, the intended demo key) and 5 obviously-mock keys in `test/fixtures/mock-zkool-fixture.json`. No mainnet key, address or txid of the owner's mainnet watcher appears.
- Mock fixture seed text is `MOCK SEED (not a real seed phrase)`.
- Server: `ss -ltn` shows `127.0.0.1:4747` only; `startServer` throws for any other host (`src/server.js` line 24).
- Cross-origin POST: `Origin: http://evil.com` returns 403; `Sec-Fetch-Site: cross-site` 403; `Origin: null` 403; `Host: evil.com:4747` 421 (DNS rebinding); `content-type: text/plain` 415; same-origin POST accepted. Bodies capped at 16 KB.
- Key refusal (API and CLI): seed phrase, `secret-extended-key-test…`, `usktest1…`, `usk1…` all return "SPENDING key / seed phrase" errors that do not echo the input; mainnet key on testnet and testnet key on mainnet refused ("Networks are never mixed"); `uviewtest1abc`/`uivk1abc` "Malformed". `connect` also refuses a zkool account that holds a seed.
- `data/` perms: dir `drwx------`, files `-rw-------` (observed on the throwaway dir). CSV formula guard works (`=cmd|calc` becomes `'=cmd|calc` in invoices.csv).
- Receipt tamper test: multiplying `amount_zats` by 10 gives "hash MISMATCH", "MISMATCH amount_zats", "NOT VERIFIED", exit code 1. `sha256sum -c MANIFEST.sha256` all OK.
